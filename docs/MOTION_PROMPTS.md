# MOTION_PROMPTS · 动效提示词库与设计经验

> 来源：用户提供的「动效参考库」9 类 90 条。
> 参数基准：30fps、横屏 1920 宽。本项目成片是 1080×1920 竖屏，使用前按第 2 节换算。
> 用途：写分镜、给代码生成模型下指令、拆成本项目的生成配方。

## 0. 一句话用法

先定叙事角色（hook / build / proof / turn / close），再定素材粒度（scene / overlay / transition / post），然后从 9 类里选 1 条主运动，必要时加 1 条次级运动，补 1 个转场或后处理和 1 个音效。每条只用一个代号，参数按公式补齐。

## 1. 经验总结

### 1.1 一条只做一件事

每条只描述一个可命名的动效。名称是检索键，提示词是执行配方。不要把入场、强调、退场、转场混在一条里。

### 1.2 用状态变化代替形容词

公式：

```text
对象 + 起始状态 → 结束状态 + 缓动 + 时长(帧) + 错峰 + 落点/过冲 + 音效/触发
```

反例：「优雅地出现」「快速推近」。
正例：「每个字从下方 0.6em、透明度 0 到位，outExpo 16 帧，字间隔 1.5 帧」。

### 1.3 参数必须可度量

- 时间：帧（30fps）；16 帧约 0.53s。
- 缓动：outExpo / outQuint / outQuart / outCubic / outBack / inOutExpo / inOutCubic / inOutSine / inExpo / spring。
- 位移：em（文字）、px（画面）、%（相对元素或屏幕）。
- 错峰：1.5–4 帧最常见。
- 过冲：6% 常见；大字砸入从 1.6 倍回到 1 倍。
- 衰减：冲击抖动 8px + 1° 在 10 帧内指数衰减。
- 后处理透明度：颗粒 0.2–0.3、扫描线 0.08、暗角 0.6–0.8。
- 没有数字的参数，等于没写。

### 1.4 写清触发、落点、退场

- 触发：入场即开始 / 句子出现 1 拍后 / 重音帧 / 拍点。
- 落点：到位帧要有落点，如过冲、回弹、闪白、抖动、残影。
- 退场：入场与退场成对。E10 反向退场 = 入场反向 + 65% 时长 + 反向错峰。
- 没有落点的动画会显得飘；没有退场的元素会硬切。

### 1.5 指定层级与合成方式

每条都要能回答：全屏 / 叠加 / 转场 / 后处理？是否需要 alpha？是否循环？是否覆盖文字安全区？

- `scene`：全屏实底或透明背景，通常 3–6s。
- `overlay`：透明 WebM，通常 1–3s，叠在实拍或生成画面上。
- `transition`：0.3–1s，短、可复用、带音效。
- `post`：低透明度后处理层，不单独成片。

### 1.6 声音是节拍的一部分

打字机配打字音、故障切配 glitch、快速变焦配 whoosh、大字砸入配 impact、转场配 whoosh / riser。
没有音效的「落拍」通常不成立；音效要落在同一帧或提前 1–2 帧。

### 1.7 确定性

粒子、噪声、随机旋转、乱码字符必须用固定种子；抽帧和颗粒每 N 帧换图，必须可复现。
本项目红线：`src/` 禁止 `Math.random` / `Date.now` / `new Date`；用 `keyedRandom(seed, key)` 或 Canvas 引擎的 `rng(seed)`。

### 1.8 主运动 + 次级运动

主运动负责叙事，如入场、转场、强调；次级运动负责「活着」，如 ±4px、周期 3–4s 的 inOutSine 漂浮，或 0.5°/s 旋转。
没有次级运动的静止画面就是死帧；次级运动过大则会抢戏。

### 1.9 先叙事角色，再动词，再条目

| 角色 | 目标 | 常用条目 |
|---|---|---|
| hook | 抓注意力 | T07 / T06 / E03 / X08 / C06 / P02 |
| build | 建立信息 | E01 / T02 / S01 / D01 / C01 |
| proof | 给证据 | D02 / D03 / D06 / U02 / U03 / C09 |
| turn | 转折 | X04 / X05 / X09 / F08 / C02 |
| close | 收束 | T05 / E10 / F02 / F06 / C01 |

这个顺序比「先选好看的效果」更稳。

### 1.10 可验收

每条提示词都要能回答「渲染出来怎么判断合格」：

- 首帧、落点帧、末帧分别是什么状态？
- 位移、透明度、缩放是否到位？
- 有没有死帧？
- 有没有遮挡主体或文字？
- alpha 边缘是否干净？
- 30fps 下时长是否准确？
- 音效是否对齐？
- 同一 seed 重渲是否一致？
- 是否超出安全区？
- 是否和已有素材重复？

### 1.11 常见反模式

- 用形容词代替数值：「自然一点」「稍微快一点」。
- 一条里塞多个效果：入场 + 强调 + 退场 + 转场。
- 只写入场，不写退场。
- 不写层级与合成方式，不知道是全屏还是叠加。
- 绝对 px 不带基准宽度。
- 随机不带 seed，无法复现。
- 忽略文字长度、断行和安全区。
- 后处理过重，颗粒或辉光盖过主体。
- 所有镜头用同一种缓动，节奏扁平。
- 转场比镜头还长。

### 1.12 参数速查

| 参数 | 常用值 |
|---|---|
| 快节奏入场 | 10–16 帧 |
| 电影感入场 | 20–30 帧 |
| 文字错峰 | 1.5–4 帧 |
| 元素错峰 | 3–4 帧 |
| 过冲 | 6% |
| 大字冲击 | 1.6 倍 → 1 倍，4 帧残影 |
| 抖动 | 8px + 1°，10 帧衰减 |
| 持续漂浮 | ±4px，3–4s，inOutSine |
| 转场 | 8–16 帧 |
| 颗粒透明度 | 0.2–0.3 |
| 扫描线透明度 | 0.08 |
| 暗角边缘透明度 | 0.6–0.8 |

## 2. 竖屏适配（1080×1920）

### 2.1 单位换算

- 横屏基准 1920 宽 → 竖屏 1080 宽：横向 px 乘以 0.5625，或改成 % / em。
- 纵向不要按 0.5625 缩：竖屏高度 1920，比横屏 1080 更高；纵向位移按高度比例或保留 px 后目测。
- 文字用 em / 相对字号，不要用绝对 px 写死。
- 粒子数量：1920×1080 与 1080×1920 的像素面积相同，约 207 万，数量可沿用；分布改为纵向。

### 2.2 文字

- 单行 8–10 个中文；最多 2–3 行。
- 文本安全宽度约 920px，即 85% 宽。
- 安全区：上 120px、下 220px、左右 60–80px，给平台 UI 留位。
- 字号：主标题 90–140px；副标题 48–72px；标签 28–40px。
- T 类动效必须先有文本内容和断行规则，否则无法渲染。

### 2.3 镜头与转场

- 竖屏纵向空间更多，适合 C01 推近、C09 拉远、C03 2.5D 视差。
- 横向平移容易露出裁切黑边；带 `crop` 的素材继续锁定裁剪中心，只用 push / pull / still。
- 转场优先纵向或斜向，如 X02 斜切、X09 墨滴、X10 光漏；少用纯横向擦除。
- 转场时长 8–16 帧；超过 20 帧会拖节奏。

### 2.4 安全区与合规

- 生成画面是示意；UI mock 必须带「示意」标记。
- 品牌图标只作类别示意，不表示合作或背书。
- 来源、出处、平台声明不上屏；只进 `CREDITS.md`。
- 不写绝对说法；CTA 直接指向主页。

## 4. 配方字段（建议）

```json
{
  "id": "t01-char-rise",
  "code": "T01",
  "name": "逐字上浮",
  "engine": "text",
  "layer": "overlay",
  "beatRoles": ["hook", "proof", "close"],
  "durationFrames": 16,
  "alpha": true,
  "loop": false,
  "params": {
    "distanceEm": 0.6,
    "ease": "outExpo",
    "staggerFrames": 1.5,
    "opacityFrom": 0
  },
  "text": {
    "maxCharsPerLine": 10,
    "maxLines": 2,
    "safeWidth": 920
  },
  "tags": ["text", "entrance", "emphasis"],
  "version": 1
}
```

字段说明：

- `engine`：渲染引擎，不是 preset 名。
- `layer`：`scene` / `overlay` / `transition` / `post`。
- `beatRoles`：可插入的节拍角色。
- `durationFrames`：30fps 下的帧数。
- `alpha`：是否出透明 WebM。
- `loop`：是否可无缝循环。
- `params`：引擎参数；所有随机项必须有 seed。
- `text`：文本约束；非文本动效可省略。
- `version`：配方版本；改参数要升版本，避免命中旧缓存。

## 5. 选择流程

1. 定叙事角色（hook / build / proof / turn / close）。
2. 定粒度（scene / overlay / transition / post）。
3. 选类别（T / E / X / C / S / D / P / F / U）。
4. 选 1 条主运动；需要时再加 1 条次级运动。
5. 按第 2 节换算竖屏参数，补音效和验收帧。
6. 渲染 3 张静帧 + 1s 预览；先看静帧，再看动态。
7. 通过验收清单后，再登记为 `approved`。

## 6. 验收清单

- [ ] 首帧、落点帧、末帧状态明确。
- [ ] 位移、透明度、缩放、旋转到位，无过冲越界。
- [ ] 无死帧；静止元素有次级运动。
- [ ] 不遮挡主体、文字、平台 UI 安全区。
- [ ] alpha 边缘干净；无黑边、白边、灰边。
- [ ] 30fps 下时长准确；转场 8–16 帧。
- [ ] 音效与落点同帧或提前 1–2 帧。
- [ ] 同 seed 重渲一致；无 `Math.random` / `Date.now`。
- [ ] 画面上无内部标签、来源角标、分镜描述词。
- [ ] 与已有素材的 pHash / 签名不重复。

## 9. 维护

- 新增条目：先补全第 4 节字段，再在对应类别表追加一行。
- 改参数：升 `version`，旧渲染缓存不失效会命中原参数。
- 新增引擎：先更新 `docs/MODULES.md`，再登记依赖与素材。
- 本文件是设计参考，不是运行时数据；真正消费它的配方在 `creative/` 的引擎与变体里。
